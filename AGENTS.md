## Learned User Preferences

- Luca wants one-time setup followed by fully automatic behavior; he rejected opening projects via a CLI command and pushed for automatic profile/key selection instead (companion extension, shell wrapper, aliases).
- New tool repos should follow his micro-tool mold (reference repos: wip-ai, cursor-cost, key-guard): sharp README with ASCII banner, single-file GitHub Pages landing page in `docs/`, entry in the L-ubu.github.io hub registry, and a filled-in GitHub About (description, homepage URL, topics).
- Commits and written repo content use conventional commit messages, no co-author trailers, and no em-dashes (his hard rule; use `·` or colons instead).
- Tools built for sharing must stay generic: no hardcoded personal paths or project names in the repo; per-user state lives outside the repo.
- Public-facing docs (README, Pages site) must be scrubbed of employer-identifying info before release: no internal project names, internal URLs, or other private details; he explicitly asked to remove them to avoid leaks.
- Drafting workplace communications is iterative, message by message: critical-but-constructive and evidence-led (screenshots, links, numbers) for feedback threads (e.g. the Bonzai rollout), short and personal for announcements (e.g. the cursor-keys launch post); concede fair points, end with a concrete ask; expect several trim/rework rounds as the thread evolves.

## Learned Workspace Facts

- This repo is `cursor-keys` (npm package name, public GitHub repo `L-ubu/cursor-keys`; local folder is named `api-key-switcher`): per-project Cursor profiles so each Cursor window bills the correct BYOK API key. Works with any OpenAI-compatible gateway (LiteLLM, Vercel AI Gateway, ...).
- Core constraint driving the design: Cursor stores API keys profile-globally (no workspace-level key setting, no env var support, no extension API to change keys), so each project gets an isolated `--user-data-dir` profile under `~/.cursor-profiles/<name>/`; fully automatic key switching inside a single window is impossible.
- Stack: Node >= 18, ESM `.mjs`, zero runtime dependencies; tests via `node --test`; CLI entry `bin/cursor-keys.mjs` (bins `cursor-keys` and `ckeys`); modules in `src/` (config, detect, profile, keychain, commands, jsonc, ansi); companion Cursor extension in `extension/`; Pages site in `docs/index.html` with amber accent `#fbbf24`.
- `set-key` encrypts project keys with Cursor's own safeStorage mechanism (Chromium OSCrypt; password read at runtime from the "Cursor Safe Storage" macOS Keychain item) and writes the `secret://cursorAuth/openAIKey` row into the profile's `state.vscdb`, round-trip verified; key injection is macOS-only, Windows/Linux users paste the key once per profile manually. Sourcing the password via 1Password (`op` CLI) for cross-platform support was raised Oct 15 but is not implemented.
- Per-user config lives at `~/.config/cursor-keys/config.json` (never committed); gateway base URL is set via `cursor-keys config baseUrl` (URL-validated), fresh installs get a built-in default until overridden. Durability fixed in 1.2.3 after wipes observed Oct 13 and Oct 15: `saveConfig` writes atomically (tmp file + rename) and every mutation goes through `updateConfig` (fresh load → mutate → save), so concurrent runs merge instead of clobbering; tests and scripts can point at a scratch config via `CURSOR_KEYS_CONFIG_FILE`.
- Settings sync is one-way from the main profile: `cursor-keys sync [name]` re-copies main's `settings.json` into profiles while re-applying each profile's title bar color, and `open` auto-syncs before every launch; keybindings and snippets are symlinked to main; API keys and sign-in/model state are deliberately not synced (state DB changes need `clone`).
- Distribution: CLI published on npm as `cursor-keys` (right after `npm publish` the registry lags: poll `npm view cursor-keys@<v> version` until it propagates, then install); companion extension published on Open VSX as `lubu/cursor-keys` and auto-linked into `~/.cursor/extensions` by the npm postinstall on global installs (1.2.3+; `CURSOR_KEYS_NO_POSTINSTALL=1` opts out).
- This project handles real API keys and Cursor keychain material: never write keys, encrypted key blobs, or keychain passwords into files, logs, stdout, commits, or memory notes; always fetch secrets dynamically at runtime. Secrets pasted in chat are treated as burned (API keys during the build session, an npm publish token on Oct 13).
- Out of scope or unreachable: gateway stress-testing and benchmarking stay outside this repo (Luca's explicit rule; external bench tooling may import this repo's `src/` helpers, so keep their export names and signatures stable); `cursor-agent` CLI (checked v2026.10.01) has no BYOK/base-URL config surface, so CLI usage cannot be routed through profiles and bills to the central seat.
- Releases: 1.2.2 (Oct 15) was the UX polish bundle · banner/tagline fix, ANSI-aligned status table, `ck` alias, zsh tab completion, postinstall hint; 1.2.4 (Oct 19) added `cursor-keys color <name> [#hex]` to show/set a project's title bar color and re-apply it to the profile live, from a feature request by Davy De Pauw · in zsh quote the hex, an unquoted `#` starts a comment.
- Early iO adopters and recurring feedback sources: Maarten 'Steen' De Rammelaere beta-tested first (his feedback put `clone` into the first-run steps); Davy De Pauw followed (`profilesRoot` question, then the 1.2.4 `color` request for brand colors).
- Luca's machine: npm global prefix is `~/.local` (global installs land in `~/.local/lib/node_modules`); Warp provides compinit via shell integration even when ~/.zshrc lacks it, so the tab-completion warning is Warp/oh-my-zsh-aware since 1.2.3.
